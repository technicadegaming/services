Arcade Card Reader Charges Credits but Game Won't Start

Trace the difference between successful card transactions, start pulses, and game-controller faults.

Technicade independent technical resources · Use model-specific service documentation

Share on Facebook

Quick diagnostic path

Start with the card transaction and game start as separate events. A successful deduction does not guarantee the game controller received or accepted a start pulse. Record the amount deducted, reader response, machine display, and whether a credit counter advances.

Test a single controlled transaction

With guest play paused, use a documented test card or authorized service transaction. Write down reader ID, game ID, timestamp, charge, visible reader status, and machine reaction. Avoid repeatedly charging customer cards while testing.

Check configuration first

Confirm the reader points to the correct game record and price, the game is enabled, and the interface is configured for the correct supported pulse or protocol mode. Compare with a known-good station of the same hardware revision, after documenting its settings.

Check the start interface

With power isolated and following the manual, inspect loose connectors, pinched harnesses, corroded terminals and interface boards. Qualified personnel can use manufacturer-approved input/output diagnostics to determine whether the reader emits a start signal and whether the game sees it. Never short unknown pins or defeat interlocks.

Interpret the result

Reader transaction recorded but no output: investigate interface settings, reader diagnostics and communication. Output present but controller doesn't react: investigate wiring and game input settings. Controller increments its credits but play never starts: investigate start-button and game logic. These are hypotheses to confirm with your equipment documentation.

Handling disputed charges

Preserve logs, refund or restore credits according to venue policy, and avoid collecting full card numbers or personal data in the incident report. Share model, firmware, time of fault and sanitized logs with the vendor if the problem persists.
