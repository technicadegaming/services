Intercard iTeller Plus Upsells: Different Credit Offers for Different Packages

A practical guide to designing and testing package-specific credit upsells on Intercard iTeller Plus kiosks, with version-specific cautions.

Technicade independent technical resources · Version-specific checks recommended

Share on FacebookShare on LinkedIn

Quick answer

Start by mapping each base card package to one intended upgrade, then verify whether your installed iTeller Plus software supports conditional offers for that kiosk. Intercard publicly confirms upselling on the iTeller PlusXL platform, but exact administrator screen names and availability can differ by version. Don't change live offers until you can test every package and payment path.

Does iTeller Plus support upsells?

Intercard advertises upselling on its iTeller PlusXL kiosks and says that offers may reflect the guest's initial selections. That supports the general idea of varying the offer by the original package. It does not establish an identical configuration procedure for every older iTeller Plus model or software revision.

The fastest reliable approach is to identify the kiosk model, installed iTeller software version and Back Office permissions first. If you do not see an upsell configuration screen, ask Intercard support for the instructions matching that installation rather than following unrelated screenshots.

Create a package-to-upgrade worksheet

For each existing package, write down its name, price, purchased credits, promotional credits, any time restrictions and intended upsell. Treat the following as an illustration, NOT an Intercard preset:

  • Base package A: $20 purchase; optional upgrade to a $30 total package.
  • Base package B: $35 purchase; optional upgrade to a $50 total package.
  • Base package C: $60 purchase; optional upgrade to a $75 total package.

For each line, clarify whether the guest is paying the difference to replace the package or purchasing an additional item. Also clarify whether the extra amount becomes purchased value or bonus play. These distinctions affect both the receipt and card balance.

Match conditions to the original purchase

In your installation's supported configuration interface, the logical requirements to confirm are:

  1. Which original product/package triggers an offer?
  2. Which upgraded product is shown, and on which kiosk?
  3. Whether acceptance replaces the original selection or adds a second product.
  4. The total charged and how purchased versus bonus value is assigned.
  5. Whether any other promotion or existing bonus conflicts with the offer.

These are decision points to verify, NOT claimed menu labels. The detailed click path has not been publicly confirmed for all Intercard deployments.

Run a controlled kiosk test matrix

Before turning on offers for guests, use an authorized test payment or test card:

  • Select each base package and record whether the intended upsell appears.
  • Decline it and verify the original package and charge remain correct.
  • Accept it and verify the actual total, receipt, purchased credits and bonus value.
  • Repeat with existing-card reloads as well as new-card purchases if both are enabled.
  • Test time restrictions and promotion stacking, if applicable.
  • Confirm that updates propagate to every relevant kiosk and that reporting matches the transaction.

If the wrong upsell appears

First confirm that the original package really matches the condition you configured. Next compare package IDs versus display names, kiosk assignment and the current version of the software. If the offer is correct but the balance isn't, focus on purchased-value and bonus-credit mapping rather than simply increasing the offer amount.

What to ask Intercard support

Send the iTeller model, installed version, an example base package and desired upgrade, and ask for the documented way to associate distinct upsell offers with distinct original packages. If possible, provide a screenshot with customer details redacted.

This independent guide explains the workflow to validate. It is not a substitute for Intercard's version-specific administrator training.
